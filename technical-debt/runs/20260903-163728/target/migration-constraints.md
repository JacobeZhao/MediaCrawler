# Migration Constraints

1. Preserve the four user-owned files unless an exact attributable hunk, R2 reference, and focused oracle are approved.
2. Preserve HTTP routes/payloads/statuses, task/provider identity and queues, checkpoints/budgets/retries, single-process deployment, DB schemas/paths/data, Uvicorn entry, static frontend behavior, and documented Python imports.
3. Establish `TD-001` before broad pass/fail claims; characterize affected behavior before each extraction.
4. Use compatibility facades during module splits; remove only after internal-zero and supported external-consumer evidence.
5. Execute one coherent responsibility change per batch with exact allowlist, R1/R2 recovery, focused tests, then proportional broad gates.
6. Do not inspect or mutate `.env`, runtime DBs, browser profiles, exports, backups, uploads, credentials, or production/external systems.
7. No real migration, package installation, network probe, commit, push, deployment, or remote mutation is authorized.
8. Security/release/destination/duplicate policies remain blocked until explicit decisions; continue independent goals.
9. Do not replace/re-encode vendored or inherited bytes without provenance/encoding proof.
10. After any accepted write, refresh HEAD, dirty attribution, coverage, dependency edges, live state, goal matrix, change history, and gates.
